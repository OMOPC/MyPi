# 设计原则

1. 通常而言，模型的输出token比输入token贵，因此，工具应当做到：
    1. 较少的输入要求
    2. 尽可能多的有效结果，亦即有价值的信息。
    3. 任何输出的静默降级，都应该明确告知模型降级的事实与解决的方法。
2. 未生效的工具不允许进入模型上下文，不允许让模型知道。

## 效率类

bash工具（仅以bash为例，其它平台自动对应pwsh、zsh等）本身提供非交互的命令行，可以运行几乎所有命令。

因此，如果一个工具可以被一次bash命令代替，说明它不是一个好工具。亦即，此类工具设计的基本原则，是至少能替代两次必然不连续的bash命令。

本类工具包括：

- bash
- read
- write
- edit/splice
- grep
- alias
- kairos
- mcp

其中，splice和edit是互斥的编辑工具，不允许同时启用，两者同时启用时，实际仅有splice生效。

本类工具的文本编辑类，针对rust语言（未来的go、py以及文档语言，亦即md）做特殊优化，其它语言死一边去。

## 记录类

此类工具起到记录跨压缩甚至跨会话记录信息、形成「额外上下文储备之用」。

本类工具包括：

- context
- memo
- todo

## 浏览器类工具

浏览器工具，以最常见、兼容性最好的chromium系为首要支持目标，firefox系暂时不予考虑。

浏览器工具启动时，应当尽可能避免所有自动化特征，打开正常的窗口，以用户可见的方式允许Agent操作有固定profile的浏览器，在此基础上，我们希望这一工具能具备绝大多数浏览器操作的能力（除了过人机验证），以实现用户目标。

此类工具设计原则：
1. 最大伪装
2. 实用导向

浏览器工具的设计目标应当是允许模型替用户完成资料收集工作，因此，爬虫网络调试、css样式调整等，留给mcp去做。

本类工具包括：
1. search
2. web

## 子代理

子代理工具，以模板+变量，兼顾灵活性和减少模型输出token之用。

子代理，需要由模板指定拥有的工具，使用时必须填充模板内变量（没有变量时不用）。

子代理上工过程与主代理全程隔绝，不允许中途交流，也不做相关支持。

# 打断

工具的打断，应当分情况视为：
1. 有复杂流程、时间等待的，取消之后的流程，直接返回已经获取的结果，并在末尾标注：interrupted by user
2. 没有复杂流程，几乎立刻出结果的，不打断工具本身运行，但是打断之后的http连接，也就是实际上起到打断网络连接的效果。
3. 亦即，总体原则是：接下已经运行出结果的部分，扔掉之后的流程，并标明是用户主动打断。
