# 设计

splice是一个基于行号编辑的特化工具。

使用old new的edit工具，配合给出行号的read，并不能有效利用read给出的信息，因为行号和old new没有半毛钱关系，亦即，使用old new编辑时，给模型行号只会增加无效输出。

已知：rust的严格语法，以及fmt等格式化的现成工具，可以帮我们抓出rs文件中的关键字，例如，impl，fn，pub fn，match，if等。

那么在read这一层解析好对应关键字所在的行，仅返回这些行的行号，能有效减少无效输出。

因此，splice必须与read搭配使用，也许未来会打算加入形同`68 impl sth for another`的首词匹配规则，但现在仅以行号为编辑锚点。

在完成编辑后，模型往往需要cargo check进行语法检查，因此，在splice、edit、write这类涉及到改写文件内容的工具调用后，我们直接接上fmt对每一个edit进行格式检查，并在批次调用后直接接上一次cargo check，并将报错信息如实返回。

对于正处于模型修改区间的报错信息，我们直接将其插入原文与改文的diff中，对于无法定位/定位到模型修改区间外的报错信息，以`文件位置 - 报错原因 - help信息`的一行流，按照cargo自己的检查顺序返回即可，依次，在编辑过程中，我们已经完成了对修改内容的语法格式检查，以及模型几乎必然自己动手的cargo check。
